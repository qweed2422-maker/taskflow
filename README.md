# TaskFlow

Веб-приложение для управления задачами внутри небольшой команды.
Учебный проект на Django 4.2, рассчитан на работу в локальной сети.

## Возможности

- проекты: создание, редактирование, удаление (руководитель), просмотр (все);
- задачи: автор, исполнитель, статус, приоритет, дедлайн, прикреплённый файл;
- комментарии к задачам;
- поиск по названию, фильтры по статусу, исполнителю и проекту, пагинация;
- дашборд со статистикой (по статусам, приоритетам, просроченные задачи);
- вход и выход, две роли с разграничением доступа;
- Django Admin для руководителя.

## Роли и права

| Действие                                  | Руководитель | Сотрудник                         |
|-------------------------------------------|:------------:|:---------------------------------:|
| Просмотр проектов                         | все          | все                               |
| Создание, изменение, удаление проектов    | да           | нет                               |
| Просмотр задач                            | все          | только где он автор или исполнитель |
| Создание задач                            | да, с назначением исполнителя | да, автором становится он сам |
| Редактирование задач                      | любых        | только своих (без смены исполнителя и проекта) |
| Смена статуса                             | любых        | своих                             |
| Удаление задач                            | да           | нет                               |
| Комментарии                               | к любой задаче | к задачам, которые ему видны    |
| Django Admin                              | да           | нет                               |

Защита от доступа к чужим данным строится на фильтрации queryset в каждом view
(`Task.objects.visible_to(user)`), а не на скрытии кнопок. Если сотрудник подставит
в URL id чужой задачи, он получит `404`. Удаление и операции с проектами
защищены отдельно и дают `403`.

## Технологии

- Python 3.10-3.12
- Django 4.2
- SQLite
- Bootstrap 5 (подключается с CDN)


## Установка

Требуется Python 3.10-3.12 и Git.

```bash
git clone <адрес-вашего-репозитория>
cd taskflow
python -m venv .venv
```

Активируйте окружение:

```bash
# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Linux / macOS
source .venv/bin/activate
```

Установите зависимости и подготовьте базу данных:

```bash
pip install -r requirements.txt
python manage.py migrate
```

Команда `migrate` создаёт таблицы и две группы ролей: `Managers` и `Employees`.

## Тестовые данные

```bash
python manage.py loaddata fixtures/db.json
```

В фикстуре: 1 руководитель, 4 сотрудника, 4 проекта, 14 задач с разными статусами
и приоритетами (часть просрочена), несколько комментариев.

| Роль         | Логин                                      | Пароль          |
|--------------|---------------------------------------------|-----------------|
| Руководитель | `manager`                                   | `Manager2026!`  |
| Сотрудники   | `employee1`, `employee2`, `employee3`, `employee4` | `Employee2026!` |

Руководитель также имеет доступ в Django Admin: `/admin/`.

Данные можно сгенерировать заново командой
`python manage.py seed_demo_data --reset` (удаляет проекты, задачи и комментарии
и создаёт их заново, пользователей и группы не затрагивает).

## Запуск

```bash
python manage.py runserver
```

Откройте http://127.0.0.1:8000/ и войдите под одной из учётных записей выше.
Для работы с чистой базой создайте руководителя вручную:

```bash
python manage.py createsuperuser
```

После этого добавьте этого пользователя в группу `Managers` через `/admin/`.

## Запуск в локальной сети

1. Узнайте IP-адрес компьютера в локальной сети (`ipconfig` в Windows,
   `ip addr` в Linux), например `192.168.1.50`.
2. Добавьте этот адрес в `ALLOWED_HOSTS` в `taskflow/settings.py`:

   ```python
   ALLOWED_HOSTS = ['127.0.0.1', 'localhost', '192.168.1.50']
   ```

3. Запустите сервер на всех интерфейсах:

   ```bash
   python manage.py runserver 0.0.0.0:8000
   ```

4. С других устройств сети откройте `http://192.168.1.50:8000/`.

Если страница не открывается, проверьте, что брандмауэр разрешает входящие
подключения на порт 8000.

> Режим `DEBUG = True` и встроенный сервер `runserver` предназначены только
> для разработки и работы в доверенной локальной сети.

## Загрузка файлов

Файлы задач сохраняются в папке `media/tasks/ГГГГ/ММ/`. В режиме разработки они
раздаются самим Django по адресу `/media/...`. Папка `media/` не хранится в Git.
